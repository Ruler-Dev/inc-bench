inc-bench
—

Il loop agentico in diretta: il modello chiede un tool, l'harness lo esegue in Python e rimanda il risultato, finché il modello non risponde senza tool call. I sub-agenti sono riquadri tratteggiati: hanno un contesto vuoto e meno tool.

System prompt e tool disponibili

  

  







  
Una tool call, byte per byte. Il modello non esegue niente: vede uno schema, scrive un JSON
    di richiesta, e l'harness fa tutto il resto.

  

    
    
  

  







  
Forzare uno schema: solo con il prompt (parse + validazione + retry) oppure con il
    constrained decoding lato server (response_format: json_schema, lo stesso principio di
    XGrammar/GBNF). Il secondo garantisce la forma, ma nessuno dei due garantisce la verità.

  

    
    
  

  

    
    
    
  

  







  
Stessa fattura, due approcci. A: il modello fa i conti e risponde con un JSON (schema forzato).
    B: il modello sceglie solo il tool, e i numeri li calcola uno script Python deterministico.
    Lo schema di A è sempre rispettato: la forma non è la verità.

Compilare un JSON lungo da un'email d'ordine scritta a mano: una voce per riga (6 campi) più i totali.
    Tre strategie a confronto. I validatori (Python) controllano tutti gli output senza conoscere la verità.
    Il giudice LLM è un agente revisore: aiuta, ma il benchmark misura anche quanto sbaglia.

  

    
A Tutto al modello

      
LLM: estrae + calcola tutto

      
1 chiamata. JSON forzato dallo schema: la forma è garantita, i valori no.

    
B Modello + Python

      
LLM: estrae→Python: calcola

      
1 chiamata. I conti sono giusti, ma l'estrazione di una lista lunga in un colpo può perdere o sbagliare righe.

    
C Pipeline multi-agente

      
Splitter→Estrattori ×K ∥→Validatori→Correttore→Giudice→Calcolatore

      
JSON piccoli in parallelo. Ogni valore deve comparire nel testo, altrimenti la riga torna al correttore con l'errore esatto.

Chi si accorge degli errori?

  







  
Classificare incidenti di cybersecurity da un corpus di documenti enormi: log SIEM, alert EDR,
    threat intel, inventario, note degli analisti, email e policy. Il corpus contiene trappole: riclassificazioni successive,
    falsi positivi dichiarati via email, righe che citano un incidente senza appartenergli, frasi che negano un collegamento.
    I campi sono valutati per tipo: deterministici ×6 (si calcolano dai log),
    semantici ×1 (la categoria: bisogna capire il testo),
    derivati ×2 (severità e MITRE: regola fissa sulla categoria).

  

    
S Solo script

      
regex + regoleparole chiave

      
0 chiamate LLM. Deterministici al 100%; la categoria con parole chiave (solo i nomi delle categorie) indovina solo quando il testo la nomina.

    
A Solo LLM

      
tutto il corpus → JSON

      
1 chiamata con l'intero corpus. Se non entra nel contesto del modello, fallisce.

    
B LLM per incidente

      
retrieval→LLM compila tutto ∥

      
Contesto piccolo per ogni incidente, ma l'LLM conta, ordina date e applica la policy. Nessun controllo.

    
C Ibrido multi-agente

      
script: 6 campi→retrieval→classificatore ×2 ∥→arbitro→validatori→correttore→giudice→severità + MITRE

      
L'LLM decide solo la categoria, con una citazione; due opinioni indipendenti e un arbitro se non concordano.

Il loop

    
messages = [system, user]→
      LLM(messages, tools)→
      tool_calls?sì →
      esegui in Python→
      aggiungi role="tool"↺
      no →risposta finale

    
Tutto il resto (permessi, contesto, retry, log) è contorno. Codice: harness/agent.py.

  

    
Tool
Funzione Python + descrizione + JSON Schema. Il modello vede solo lo schema;
      arguments è una stringa che l'harness deve parsare e validare.

    
Skill
Cartella con SKILL.md e scripts/. Nel prompt va solo
      l'indice: il modello carica le istruzioni quando servono (progressive disclosure).

    
Sub-agente
Lo stesso loop, con il contesto vuoto e meno tool. Al padre torna solo
      il risultato finale: il contesto principale resta pulito.

    
Schema forzato
Il constrained decoding (XGrammar, GBNF) rende il JSON valido
      per costruzione. Non rende veri i valori: per i calcoli serve codice deterministico.
